## 设计与边界

原角色分配 API 和动态扩展保持不变。新入口先调用原授权，再对真实账号及事务内数据库读取的角色、领域、目标租户和组织快照执行完整附加检查。仅支持目标租户用户；范围非目标租户的场景不开放。快照必须由可信后端在同一事务完整查询并提供权威数量，不能接收客户端内容；空目录、截断、重复、跨租户、缺失目标组织或不可用租户失败关闭。不得通过修改共享缓存使未提交数据可见。调用方负责数据库事务隔离、实际角色事实比对及目录/授权变化时重校验；操作者既有权限缓存失效仍遵循宿主实现。

## 签发人快照与扩展边界
原目录快照不能固定操作人读取；它不足以防止检查期间权限缓存改变。新的严格入口须先执行真实 bean 原授权以保留扩展否决，再在同线程绑定真实用户与完整权威角色、权限、租户、领域和组织的只读服务视图重复完整检查，默认方法必须以视图自身为 this。不得接受客户端数据、伪造用户、复用旧 DomainAccess 上下文；未知扩展、动态规则或无法证明隔离时失败关闭。调用方须以同一事务数据库隔离或全体写入方遵循的锁防止更新与幻读到提交；仅靠行锁和计数不足以防止不存在的公共角色租户覆盖行被插入。操作人字段与成员角色均须真实固定。旧快照接口不得用于声称具备这些保证。

业务覆盖回调需要比较单一有效角色自身的租户、领域、组织和密级范围。必须使用真实操作人解释 DEFAULT，不伪造用户；原范围算法中基于用户全部角色的全局/租户管理员快捷路径不能用于该单角色判定。不能证明包含时拒绝，用户最终范围也不得被忽略。字段组与值域覆盖仍由业务回调以同一角色单独验证。

严格视图绑定后、首次执行授权 hook 或读取动作前，可信 participant 必须同步绑定同一一致版本的不可变动作及字段目录；其生命周期覆盖全部真实 bean hook 和同角色业务覆盖检查，并在所有异常路径先关闭目录再解除线程视图。多个并发 registry 逐一复制不构成一致快照，调用方必须具备共同版本/锁或失败关闭；禁止异步及嵌套。代理对象需识别并审计确切目标类及安全 hook；不能以继承 marker 信任未知子类，也不能为了兼容代理跳过审计。

四段普通通配授权允许保守符号覆盖：签发人的每一段只能是单独 `*` 或与目标段完全一致；两式必须恰好四段，复合 `@` 表达式及其他复杂蕴含不在该证明内。该证明只处理动作表达式，不能替代同角色范围、字段组、值域或稳定目录验证。

严格视图内集合复制不代表引用的 JPA 实体不可变。签发人、目标及全部角色、租户、组织、领域须使用与 JPA 一级缓存和共享缓存脱离的深度不可变授权事实，排除未经审计的扩展行为；数据库锁不能阻止同事务 Java 对象修改。公共模块增加框架已知安全字段的阶段指纹检测，发现持续修改失败关闭；此检测不覆盖未知插件字段、修改后恢复或方法外部副作用，也不保证方法返回到提交之间的稳定性，不能取代业务不可变投影和事务提交前保障。

邀请签发时账号/新组织尚不存在，不得冒用签发人或制造假目标通过分配检查。提供单独的 actor-only 严格签发视图：在同事务稳定目录和可信不可变动作目录中验证真实签发人的创建操作、目标租户的有效角色及受控同角色权限覆盖。真实目标尚不存在时不声称完成目标数据范围验证；邀请兑换后必须继续对真实账号及实际组织执行完整的严格角色分配与单角色范围校验。任一事实来源、插件、目录或版本不能证明安全时拒绝。

签发时如果指定已有目标组织或新组织父级，必须在已绑定权威目录、隔离 DomainAccess 且目录锁仍持有的签发检查内部验证组织确属目标租户、有效并在真实签发人的组织范围内。组织不适用时可为空；调用方须按业务类型决定是否必须提供，不得把已有组织验证转移到隔离上下文外。

兑换真实账号后，严格角色分配必须在绑定权威视图及隔离领域上下文内检查 `canAdminUser`，保留领域、跨租户、密级及管理员层级拒绝；原 baseService 的该方法若被未知覆盖必须失败关闭，不回退共享缓存。签发 actor-only 阶段不存在目标用户，不伪造用户执行该检查。

会员邀请可以没有后台角色。独立的严格无角色签发入口仅用于真实无角色的业务类型，必须仍在权威视图与隔离领域上下文中执行创建动作、目标租户和组织检查以及业务 participant 覆盖；原有指定角色入口继续拒绝空角色，不能用虚构角色或空集合隐式切换。兑换业务须禁止此路径附带任何后台角色。

渠道候选/字段值范围属于签发条件，不能在严格视图解绑后回到实时缓存检查。允许传入签发阶段附加否决对象，仅在真实授权 bean 已绑定的权威视图、隔离领域缓存及受控目录生命周期内同步运行，并在原始创建/组织/角色/业务覆盖检查成功之后执行；它只能拒绝。只有真实 participant 明确认可的确切提供方可以运行，未知提供方拒绝；业务必须在渠道分支明确传入提供方，不能省略。附加检查的候选及字段值数据源仍须受同一事务与不可变目录保护。

严格视图为业务覆盖检查公开目标租户角色解析入口，直接复用现有 RoleDefinitionResolver；同码有效本租户定义优先于公共定义，重复作用域编码及请求缺失失败关闭，不在业务侧复制解析算法。调用前后校验事实指纹；外部邀请对租户覆盖的额外限制仍由业务独立施加。

平台签发人保留真实平台身份。公共组织授权新增明确目标租户的访问列表入口，在真实用户租户资格、组织范围、领域和密级约束下只读取目标租户目录；不得为兼容严格视图而枚举其他未覆盖租户或伪造用户归属。普通多租户主档过滤可使用该入口并仍以业务目标租户为约束。

受控 DAO 授权查询使用显式同步严格表达式作用域，保存并恢复当前线程解析器、拒绝嵌套及作用域内改写，隔离未知解析器并在所有变量绑定后恢复内置函数。严格作用域不代表允许执行任意表达式，调用方仍须限定受审计的表达式和上下文；普通求值行为不变。
