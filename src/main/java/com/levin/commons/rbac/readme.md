### 数据范围接入约定

- 租户、领域、组织各自有允许和拒绝集合，共六个 `Set<String>` 字段。
- 用户字段非 `null` 就替代角色对应配置，空集合也替代；仅 `null` 继承生效角色。
- 空允许集合没有授权，空拒绝集合没有排除；拒绝优先在选定来源后计算。
- 普通租户用户始终限制在自身租户内，只有平台用户具备跨租户资格。
- 组织规则为 `起点组织|匹配模式`，例如 `sales|SelfAndAllChild`；不再保存旧 `OrgScope` 对象。
- 实现 `loadAllDomainList` 和 `loadDomain` 提供 `RbacDomainInfo` 目录；`loadUserAccessibleDomainList` 批量筛选可访问领域，`canAccessDomain` 检查授权、存在性及有效状态。
- 领域是现有可访问列表和权限检查的最外层门槛：非空必须授权，空值跳过对象自身检查；原始加载参数不变，管理员不绕过领域。
- 组织与所属租户的非空领域必须一致；业务写入也必须校验。角色权限分阶段计算，避免领域和对象密级过滤递归。
- 菜单用 `filterAccessibleMenuList` 过滤并复制，不污染原始扫描缓存。

升级已有实现时，请阅读手册第 20.3 节；用户 getter 返回空集合不会再继承角色配置。

### RBAC 核心概念

1. 资源对象 `Res`
   资源有域、类型、资源标识和操作列表

2. 资源操作 `Res.Action`
   通常对应资源类型上的可执行动作

3. 资源许可 `Permission`
   许可对特定资源执行特定操作

4. 角色对象 `Role`
   角色关联权限列表，也可以带数据范围

5. 用户对象 `User`
   用户关联角色编码，也可以直接带数据范围；本租户有效同码定义优先，共享定义回退。分配时重新解析实际定义再检查，角色定义的租户不作为其领域父对象。

6. 权限检查注解 `ResAuthorize`
   可以加在类或方法上，方法上的定义可以覆盖类上的定义

7. 菜单对象 `MenuItem`
   菜单和权限分离，菜单声明自己依赖的权限

### 一句话理解

这一套 RBAC 的重点不是单纯的“用户-角色-权限”，而是把：

- 权限表达式
- 多租户
- 领域数据范围
- 组织树
- 数据机密级别

统一到了一套默认模型里。
